# LiteClean 清理行为与安全边界

本文描述 LiteClean 1.0.0 的实际实现。代码位于 `src/LiteClean.Core`，GUI 不直接执行删除。

## 1. 清理范围的确定

1. 程序只读取 **`TEMP`** 环境变量，不读取 `TMP`，也不会回退到当前目录、磁盘根目录或默认临时目录。
2. `TEMP` 必须：
   - 非空，且不是相对路径；
   - 不含 `%`、`*`、`?`、引号、`<`、`>`、`|`、NUL 等非法/未展开内容；
   - 不以点或空格结尾的名称段；
   - 位于本地固定磁盘（`DriveType.Fixed`），不是 UNC、网络盘、可移动盘或设备路径；
   - 不是磁盘根目录；
   - 实际存在、可打开，并且自身不是重解析点（符号链接/目录联接）；
   - 通过受保护位置检查。
3. 通过 Win32 句柄取得实际最终路径（`GetFinalPathNameByHandle`）作为规范根目录。短文件名会被规范化为长路径。
4. 如果 `TEMP` 位于当前用户配置文件内，则只允许位于 `%LOCALAPPDATA%\Temp` 子树；位于用户配置目录中的其他位置会被拒绝。
5. 所有候选路径会再次经过：
   - 绝对路径检查；
   - 原始字符串的点/空格结尾检查（避免 `Path.GetFullPath` 的别名归一化）；
   - UNC/设备路径检查；
   - 边界前缀检查（比较时使用目录分隔符，避免 `C:\Temp2` 被当成 `C:\Temp`）；
   - 名称段检查：拒绝空段、`.`、`..`、非法文件名字符、ADS 冒号、超过 255 字符的段；
   - 根目录本身永远不是候选。

### 受保护位置（只读常量策略）

以下位置不会被接受为清理根目录，也不会因为路径拼接而进入清理候选：

- 磁盘根目录；
- Windows、System32、WinSxS 等系统目录；
- Program Files、Program Files (x86)、Common Files；
- ProgramData、`$Recycle.Bin`、Recovery、System Volume Information、Boot、EFI、PerfLogs、Windows.old；
- 当前用户主目录、桌面、文档、下载、图片、音乐、视频、OneDrive、Public、Roaming、LocalAppData；
- 应用自身目录；
- 以及其他用户的配置文件；
- 末级名称本身属于 `Windows`、`Downloads`、`Documents`、`Desktop`、`AppData` 等敏感名称的根目录会被拒绝。

已知限制：Windows 的“已知文件夹”可能被用户移动到任意盘符。程序保护的是系统解析出的已知文件夹路径；如果 `TEMP` 被手工指向一个**未被系统登记**的用户数据目录，程序无法仅凭路径判断其业务含义。请保持 `TEMP` 为系统默认值。

## 2. 扫描（严格只读）

- 使用显式栈遍历目录，不使用无界递归，避免深层目录栈溢出。
- 每个目录单独枚举；某一个目录的异常只记录并跳过，不终止整个扫描。
- 不跟随任何重解析点：
  - 符号链接；
  - 目录联接；
  - 挂载点；
  - 其他 reparse point。
- 目录句柄以 `FILE_FLAG_OPEN_REPARSE_POINT | FILE_FLAG_BACKUP_SEMANTICS` 打开，并比较句柄最终路径与枚举路径。
- 文件检查打开一个**独占共享、带 DELETE 权限、打开重解析点本身**的句柄：
  - 证明扫描时刻文件没有被其他句柄占用；
  - 证明当前用户具有删除权限；
  - 读取卷序列号、文件索引、大小、最后写入时间、属性；
  - 通过 `GetFinalPathNameByHandle` 再次确认实际路径在边界内；
  - 这些身份信息用于清理时检测替换/竞态。
- 扫描阶段只打开句柄并读取元数据，不写入、不删除、不移动文件。
- 读取文件使用最多 4 个有界 worker（`Channel` 容量 256），目录枚举本身保持单线程，避免随机 I/O 和线程爆炸。
- 跳过规则（写入结果统计和最多 1000 条预览）：
  - 最近修改（默认 24 小时，可配置 1–720 小时）；
  - 被占用/共享冲突；
  - 权限不足；
  - 只读属性；
  - 重解析点；
  - 路径越界/非法/ADS/别名；
  - 扫描后状态变化；
  - 枚举失败/无法读取；
  - 其他无法确认安全性的错误。
- 最近文件保护是**保守策略，不是安全保证**。它不能替代占用、权限和路径检查。
- 目录候选包含所有可读取的非重解析目录。目录只有在其内容全部清理后为空时才会被删除；扫描时不会预判“必然为空”。
- 某个目录枚举失败时，该目录的候选记录会被移除，并计为“无法读取”。

## 3. 清理（独立服务）

用户必须：

1. 完成扫描；
2. 查看预览；
3. 点击“清理选中项”；
4. 在确认对话框中点击“是”。

未确认前不会启动任何删除。确认框默认按钮是“否”。

### 删除前重新校验

清理开始时重新解析并校验清理根目录。之后对每一个用户选中的候选项执行：

- 路径再次规范化与边界检查；
- 以独占、带 DELETE 权限、`FILE_FLAG_OPEN_REPARSE_POINT` 打开句柄；
- 拒绝重解析点；
- 比较文件类型；
- 比较卷序列号 + 文件索引；
- 比较文件大小和最后写入时间；
- 比较句柄最终路径与候选路径；
- 再次检查最近修改保护、只读属性；
- 在设置删除 disposition 之前再次检查取消令牌。

文件删除通过 `SetFileInformationByHandle(FILE_DISPOSITION_INFO)` 在已打开的句柄上设置删除，而不是再次按路径调用删除函数；关闭句柄后检查路径是否确实消失。这样即使扫描后路径被替换为链接、另一个文件或目录，也会被身份/重解析点/最终路径检查拒绝。

### 删除顺序

1. 文件（按扫描结果顺序）；
2. 目录按深度从深到浅；
3. 目录只在非空删除失败时记录“目录非空”，不会递归删除其中未选中的内容。

### 跳过与失败

以下情况会跳过而不是强行删除：

- 被占用/共享冲突；
- 权限不足；
- 只读；
- 最近修改；
- 重解析点；
- 扫描后大小/时间/身份变化；
- 路径越界；
- 文件/目录已不存在；
- 无法确认最终路径。

不存在的文件计为“已不存在”的跳过项，而不是失败。其他无法解释的删除错误计为失败，并保留 Win32 错误码。单个项目失败不会中止整个任务。

### 统计口径

- “预计可释放空间” = 已选中候选文件的逻辑大小之和，不代表物理磁盘一定会增加相同的空闲空间。
- “实际删除文件字节” = 在每个文件删除前，通过已校验句柄读取到的文件大小之和；只有确认删除成功后累加。
- 不把文件数量或扫描总大小当作实际释放空间。
- 空目录数量只统计真正删除成功的目录。
- 取消后：已开始的单个删除可能完成，之后不再发起新删除；不会声称可以恢复。

### 不执行的操作

- 不请求管理员权限；
- 不修改注册表；
- 不关闭/停止服务；
- 不终止进程；
- 不卸载软件；
- 不清理桌面、下载、文档、图片、视频等用户数据目录；
- 不清理浏览器密码、Cookie、历史记录；
- 不使用 CMD、PowerShell 或通配符删除；
- 不把文件移到回收站，也不提供撤销；
- 不联网、不上传文件信息；
- 不收集遥测；
- 不创建服务、计划任务或开机启动项。

## 4. 取消、UI 与任务生命周期

- 扫描和清理在 `Task.Run` 中执行，UI 线程只负责更新控件。
- `OperationCoordinator` 在锁内保证同一时刻只有一个操作：
  - 扫描中不能再扫描/清理；
  - 只有扫描成功后才允许清理；
  - 清理完成/失败后必须重新扫描才能再次清理；
  - 取消是幂等的；
  - 过期的任务完成回调会被忽略。
- 进度回调：扫描最多约每 150 ms 一次，清理最多约每 100 ms 一次，避免逐文件刷新 UI。
- 扫描取消会停止枚举和 worker，不删除任何内容；部分结果会被丢弃并显示“扫描已取消”。
- 清理取消会在当前项目边界停止，返回部分统计，`Canceled=true`。
- 关闭窗口时，若有任务运行，会询问是否取消并等待任务结束；不会在取消后继续启动新删除。

## 5. 日志与设置

- 日志目录固定为 `%LOCALAPPDATA%\LiteClean\logs`，不接收任意用户路径。
- 日志文件 `liteclean.log`，单文件上限 1 MiB，保留当前 + 2 个归档。
- 日志内容：
  - 时间、版本、清理范围；
  - 保护小时数；
  - 扫描/清理汇总计数、原因分布、耗时、取消标记；
  - 最多 30 条问题记录（相对路径、状态、原因、Win32 错误码）；
  - 不记录文件内容、凭据或完整文件清单。
- 日志写入失败只提示，不影响清理结果。
- 设置文件为 `%LOCALAPPDATA%\LiteClean\settings.json`，只保存近期保护小时数（1–720，默认 24）；读取失败回退默认值，保存采用临时文件后原子替换。
- 设置界面展示固定日志位置，并可打开日志目录。

## 6. 已知限制与不做安全保证的地方

1. **硬链接**：删除一个硬链接只删除该目录项；物理空间可能不会释放，直到最后一个链接被删除。统计按逻辑字节计。
2. **稀疏/压缩/去重文件**：统计的是逻辑文件大小，不保证等于物理空间变化。
3. **并发写入竞态**：清理前会独占打开文件并比较大小/时间/身份。若外部程序在此之后仍通过已存在句柄写入，Windows 的共享语义仍可能允许有限并发；程序会在删除前再次校验，但不能承诺对恶意并发写入的绝对原子性。
4. **文件系统/驱动特殊行为**：过滤驱动、云同步占位文件、加密文件或非 NTFS 文件系统可能有不同语义；无法确认时程序会跳过。
5. **非固定磁盘/网络盘**：明确不支持，TEMP 位于这些位置时程序拒绝清理。
6. **自定义 TEMP**：位于用户配置目录但不在 `%LOCALAPPDATA%\Temp` 下会被拒绝；这是有意的安全限制。
7. **符号链接测试**：当前测试环境没有 Developer Mode / `SeCreateSymbolicLinkPrivilege`（Win32 1314），文件/目录符号链接集成用例被跳过；目录联接用例已实际通过。代码对任意 reparse point 统一跳过。
8. **ACL 测试**：当前受限环境不允许测试进程设置 deny ACL，因此“无权限目录”的 ACL 集成用例被跳过；使用独占目录句柄的不可访问目录用例已通过。
9. **候选列表内存**：枚举是有界流式的，但为了支持逐项选择，候选路径会保留到本次扫描结束。极大规模的 TEMP（数百万项）会带来相应内存占用；尚未实现分页/磁盘索引。
10. **扫描进度**：扫描前不预先统计总数，因此扫描阶段使用不确定进度条 + 实时计数，而不是百分比。
11. **部署**：当前发布为框架依赖模式，需要 .NET 10 Desktop Runtime；未生成自包含或单文件产物（见 README）。
12. **回收站**：临时目录删除是永久删除；没有回收站模式。
